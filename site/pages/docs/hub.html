Uberblick / Docs / Sharing

Run a hub

A hub shares a workspace between computers and people. Every computer keeps its own copy and works offline; the hub passes changes on and admits only members. It is one Docker release.

Start one

Terminal
$ mkdir -p ~/uberblick-remote && cd ~/uberblick-remote
$ docker cp $(docker create --platform linux/amd64 ghcr.io/uberblick-ai/hub:0.4.7):/release/. .
$ cp remote.env.example .env
$ sh bin/remote-compose.sh up --detach

This copies the release's Compose files out of the hub image and starts the hub at http://localhost:8080, on this computer only. Documents and the claim live in named Docker volumes, so they survive restarts and updates; only down --volumes deletes them. It needs Docker Engine 28 or newer on Linux x86_64, or Docker Desktop on macOS.

Claim it

Open http://localhost:8080 and choose Sign in with GitHub, or run ub auth login http://localhost:8080. The first account to sign in becomes the hub's administrator. It reports the default workspace's id; keep it for the other computers.

Let other computers reach it

Set one route in .env, then run sh bin/remote-compose.sh up --detach --force-recreate.

RouteIn .env
Tailscale, recommended (Linux)WEB_HOST=machine.tailnet.ts.net and TAILSCALE_IP from tailscale ip -4
A public host nameWEB_HOST=hub.example.com, with port 443 open

Connect a computer

Terminal
$ ub auth login https://hub.example.com
$ ub workspace use wss://hub.example.com/ws/<WORKSPACE_ID>
$ ub open

Add people with ub workspace member add <github-handle>. To share a workspace you already have, run ub workspace promote https://hub.example.com in its project.

With Kamal

We use it with Kamal: the hub runs as an accessory next to the app.

Keep it running

sh bin/remote-compose.sh exec hub ub-hub status shows the release and whether the hub is claimed; ub-hub doctor, backup and restore do the rest. To update, back up, copy the newer release's files over the old ones the same way, and recreate. Everything else is in REMOTE.md.
