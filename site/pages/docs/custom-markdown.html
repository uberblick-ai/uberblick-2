Custom Markdown

A document is a list of blocks. Most of them are the Markdown you already write: paragraphs, headings, lists, quotes, fenced code and tables. The rest are the blocks a software team needs and a README cannot hold. Every block has a source form, so an agent writes it over MCP with insert_block or edit_block, a person edits it in the browser, and export_markdown gives the whole document back as text.

What is standard

Paragraphs, ATX headings, bullet and ordered lists, > quotes, fenced code with a language and GFM tables read and write as you expect. Inline, **bold**, *italic*, ~~strike~~, inline code and links work; a link whose target is a document id, [label](document-uuid), links to that document and counts as a backlink. A terminal fence keeps a transcript as a demonstration, with $  lines as the commands. The custom blocks below use one of two shapes: a fence with an info string for source that a program reads, or a :::name container for prose with a header.

Chart and data table

A document can own named collections of JSON records beside its prose. A chart fence holds a mapping that names a collection and its fields, never the values, so the chart is the data: when an agent writes records with update_data, every chart and table that reads them refreshes.

Markdown
```chart
{
  "version": 1,
  "type": "line",
  "collection": "deliveries",
  "x": {"field": "day", "type": "date"},
  "y": [{"field": "count", "label": "Deliveries"}]
}
```

A line chart takes one x field, a number or a date, and one to eight numeric y series with optional labels and units. layout: "panels" draws one small chart per series; missing decides whether a gap breaks or bridges a line. The same block with "type":"table" and up to thirty columns, each with a field and a text, number, date or link format, is a data table with sorting. Both omit records that fail the collection's schema and say how many they left out.

Decision record

A decision is not a block but a kind of document: a topic with a question as its title, an answer of at most three blocks at the top, then the reason and the links to the issues and pull requests it affects. Writing a new record on the same topic supersedes the old one; nothing is edited away. An agent asks find_decisions for the issue it is working on before it changes anything, and a person reads the answer first because it is the first thing on the page.

Card

A card is prose with a shape: an optional label, a required title, an optional body and footer, and any number of link buttons. Agents use it for the thing a reader should act on, such as a recommendation in a report, and the buttons can open the discussion in Claude Code or Codex.

Markdown
:::card
label: Recommendation
title: Cut the retry limit to two
footer: From the delivery report of 16 October
button: [Discuss in Claude Code](claude://code/new?prompt=Review%20the%20retry%20limit) filled blue
button: [Open the issue](https://github.com/uberblick-ai/uberblick-2/issues/1588)

Three of this week's wasted runs were third retries on the same failure. A limit of two would have stopped each one a run earlier.
:::

Header lines are label:, title:, footer: and button:, in any order; the first blank line ends the header and the rest is the body. A button is one Markdown link to an https:// address or to claude://code/new, claude-cli://open or codex://new, followed by an optional style (outline or filled) and colour (neutral, blue, green or violet).

Figma

A Figma block holds one design reference: a file, a frame, a prototype, a board or slides, with a title, a height and a caption. The page shows the title and a placeholder until the reader opens the embed, and no part of Uberblick contacts Figma on its own.

Markdown
:::figma
url: https://www.figma.com/design/k3Lm9QzT2x/Checkout-flow?node-id=12-345
title: Payment, mobile
height: 560

Card form after the **address** step.
:::

url is required and must be an https link on figma.com to a design, file, proto, board, slides or community file; the stored link keeps only the file key, the name and the node ids. title is plain text, height is 240 to 960 pixels and defaults to 480, and the caption after the blank line is inline Markdown.

Wireframe

A wireframe fence is a code block the editor draws as a screen sketch. The format is early and is being rebuilt from the ASCII sketches people already draw in issues, so that an agent can write a sketch without breaking it and a person can still read the source. Until then, the fence keeps its text.

Markdown
```wireframe
+----------------------+---------------------------+
| Pinned               |  Delivery report          |
|  Delivery report     |  Seven issues merged ...  |
|  Release plan 0.5    |  [ line chart ]           |
+----------------------+---------------------------+
```

Ablauf

Ablauf is a small text format for flow diagrams, built to replace Mermaid in Uberblick: short enough for an agent to write correctly and plain enough to read as text. It is early. Since 0.4.5 Mermaid is gone; a mermaid fence is an ordinary code block with that language and is never drawn.

Reading and writing it

Over MCP, get_doc returns the blocks with their ids, types, source text and revisions; edit_block changes one block against the revision it read; export_markdown writes the document as one Markdown file in these forms, and the CLI's ub data get and ub data update read and write the records a chart draws. The full list is in the MCP reference.
