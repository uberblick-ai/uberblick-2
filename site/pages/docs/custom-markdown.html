Custom Markdown

Markdown is a good standard, and GitHub extended it in ways that stuck. It still has one blind spot: agents produce long walls of text that nobody scans. Uberblick looks for the few additions that let an idea be drawn instead of described, a flow, a screen, a chart, and publishes each one as its own package so you can use it without Uberblick. All of them stay text. An agent writes a block over MCP, a person edits it in the browser, and export_markdown gives the document back as a file that any Markdown tool can still open. You do not have to teach your model any of this: the Uberblick MCP server carries the syntax of every block as a help topic, so an agent asks get_help("markdown") and writes it right.

What stays standard

Paragraphs, headings, lists, quotes, fenced code with a language, GFM tables and inline marks read and write as everywhere else. A link whose target is a document id, [label](document-uuid), links to that document and counts as a backlink. The additions below take one of two shapes: a fence with an info string for source a program reads, or a :::name container for prose with a header. Anything that does not know a shape sees a code block, which is the point.

Ablauf

Flow diagrams are the first thing a team wants in a design doc, and Mermaid gets half of it right: a few lines of text an agent can write, diff and review. The other half, layout, is all algorithm, so one added node reshuffles the whole chart and nobody has a handle to grab. Ablauf keeps the text and gives the layout to the author: the source names the columns, puts each node in a row, and says which side an edge leaves and enters. The renderer measures the text, draws in one house style for light and dark, and reports every crossing or overlap with a line number. It never moves anything, so an agent gets to a clean diagram from the text and the diagnostics alone, without looking at the picture. The format is early and lives in its own repository; the block in Uberblick follows it. Since 0.4.5 Mermaid is gone, so a mermaid fence is an ordinary code block with that language and is never drawn.

```ablauf
flow v0
columns agent workspace

pill change col=agent tone=agent "Update a page"
box read col=agent tone=agent "Read with get_doc"
box edit col=agent tone=agent "Write with edit_block"
box local col=workspace row=edit tone=system "Saved locally"
end synced col=workspace "Hub acknowledges"

change --> read
read --> edit
edit --> local
local --> synced
```

Wireframe

A screenshot of a mock-up is a dead end: nobody can edit it, and an agent cannot write one. A wireframe fence is a sketch as text, one element per line with a kind, a variant and a label, indented for nesting. There is nothing to balance, so an agent gets it right, and the source still reads as an outline. The editor draws it. The format is wireframe-md, published as @uberblick/wireframe; it is 0.x and may change between minor versions.

```wireframe
dialog Archive “Release plan 0.5”?
  text Readers keep the page under a muted banner. Restore brings it back.
  row.end
    button.focus Cancel
    button.danger Archive
```

Chart and data table

A chart pasted as an image is stale the day after. Here a document owns named collections of JSON records beside its prose, and a chart fence holds only the mapping: which collection, which fields. The values live in the records, so when an agent writes new ones with update_data, every chart and table that reads them refreshes, and the source stays a few lines of JSON that are easy to review.

```chart
{
  "version": 1,
  "type": "line",
  "title": "Pull requests per day",
  "collection": "pull_requests",
  "x": {"field": "day", "type": "date"},
  "y": [
    {"field": "opened", "label": "Opened"},
    {"field": "merged", "label": "Merged"}
  ]
}
```

A line chart takes one x field, a number or a date, and one to eight numeric y series with optional labels and units. layout: "panels" draws one small chart per series; missing decides whether a gap breaks or bridges a line. The same block with "type":"table" and up to thirty columns, each with a field and a text, number, date or link format, is a data table with sorting. Both omit records that fail the collection's schema and say how many they left out.

Card

A report that ends in "we recommend" loses the recommendation in the paragraph above it. A card gives it a shape: an optional label, a required title, an optional body and footer, and link buttons. Agents use it for the one thing a reader should act on, and a button can open the discussion straight in Claude Code or Codex.

:::card
label: Recommendation
title: Cut the retry limit to two
footer: From the delivery report of 16 October
button: [Discuss in Claude Code](claude://code/new?prompt=Review%20the%20retry%20limit) filled blue
button: [Open the issue](https://github.com/uberblick-ai/uberblick-2/issues/1588)

Three of this week's wasted runs were third retries on the same failure. A limit of two would have stopped each one a run earlier.
:::

Header lines are label:, title:, footer: and button:, in any order; the first blank line ends the header and the rest is the body. A button is one Markdown link to an https:// address or to claude://code/new, claude-cli://open or codex://new, followed by an optional style (outline or filled) and colour (neutral, blue, green or violet).

Figma

A Figma link in a paragraph tells you nothing until you click it. A Figma block holds one design reference, a file, a frame, a prototype, a board or slides, with a title, a height and a caption, so the page shows what it points at. The embed loads only when the reader opens it; no part of Uberblick contacts Figma on its own.

:::figma
url: https://www.figma.com/design/SSYpfPlOlUAYWfvejqmb7k/Simple-Design-System--Community-?node-id=3-5
title: Design system cover
height: 400

Cover frame of the **Simple Design System** community file.
:::

url is required and must be an https link on figma.com to a design, file, proto, board, slides or community file; the stored link keeps only the file key, the name and the node ids. title is plain text, height is 240 to 960 pixels and defaults to 480, and the caption after the blank line is inline Markdown.

Reading and writing it

Over MCP, get_doc returns the blocks with their ids, types, source text and revisions; insert_block writes an ordered array of blocks in one call, and edit_block writes one block against the revision it read; export_markdown writes the document as one Markdown file in these forms, and the CLI's ub data get and ub data update read and write the records a chart draws. The same syntax this page shows is served to the agent by get_help("markdown"), version-matched to the server it talks to, so a prompt never needs to carry it. The full list of tools is in the MCP reference. Decision records are not Markdown additions but a kind of document, with their own tools; they are on Decisions.
