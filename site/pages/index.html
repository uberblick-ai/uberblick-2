The docs folder is where context goes to die.

Every team keeps the reasoning behind its code somewhere: a Markdown folder in the repo, a Notion space, a few notebooks. The folder goes stale because nobody reads it. The wiki is far from the code and farther from the agents. The notebook is one person's.

Now most teams also have agents working in the same codebase, and they need the same context: what was decided, why, and what the numbers say. They don't need it in a chat window. They need it in a place they can search, read and edit, next to the people who wrote it.

Uberblick is that place. One workspace of documents, on your computer, built MCP first: agents write most of it, and you review and adjust in the browser. Comments sit beside the text they are about. Decisions are records, not paragraphs. Numbers live in the document that explains them.

An opinionated MCP: agents read before they write.

Agents over MCP

Tag the pages that matter as guidance. The server refuses every write from an agent that has not read them, and tells it which ones. No prompt engineering, no hoping.

1 · agentCalls edit_blockon a page in the workspace
2 · serverRefuses: guidance_requiredunread: Product principles, Web UI: typography
3 · agentReads both with get_docthe same pages people pinned
4 · serverAccepts the writeand every write for ten minutes

Works best with ub-agents.

agents.uberblick.ai

Uberblick holds what the product should do. ub-agents is the loop that hands that to agents on GitHub: roles in a few lines of YAML, driven by labels, running on Actions with any agent and no server. Together they close the loop: every issue starts from the pages, and every pull request brings them up to date. It is how Uberblick itself is built.

What a document can hold.

Custom Markdown

Markdown, plus the few additions that let an idea be drawn instead of described. Each one is text with a source form, so an agent can write it and a person can read it, and each ships as its own package.

  • ablaufFlow diagrams as text where the author places the nodes and the renderer only draws.Replaces Mermaid.
  • wireframeA screen sketch in a few lines of text, drawn by the editor.Format 0.x; it may still change.
  • chartLine charts and data tables drawn from records stored in the document.When an agent updates the records, the chart updates with them.
  • cardA prose card with a label, a title, a footer and buttons.For a recommendation, a warning or a next step an agent proposes.
  • figmaA Figma file, frame, prototype or board, with a caption.Nothing contacts Figma until the reader opens it.

Start in three commands.

Install and update

Homebrew on Apple Silicon macOS or Linux x86_64, run in your repository's directory. No account, no server. The last command registers the MCP server with Claude Code; use codex for Codex. To share a workspace, run a hub on a computer the team can reach: one Docker release, see Run a hub.

Terminal
$ brew install uberblick-ai/tap/uberblick
$ ub workspace create "My Workspace"
$ ub open
