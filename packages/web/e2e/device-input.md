# Manual device input checklist

Use Safari on a real iPad and 13-inch MacBook with a disposable document.
Playwright's WebKit covers engine behavior and device-sized layouts; these
checks cover native input it cannot reproduce. This checklist is not a delivery
gate.

| Device | Action | Expected result |
| --- | --- | --- |
| iPad | In portrait and landscape, tap a paragraph to show the on-screen keyboard, open the slash menu, then select text and open Link and Comment fields. Dismiss and reopen the keyboard. | The editor keeps focus, the active input stays visible, and the cards remain usable within the visible area. |
| iPad | With at least ten catalog tags, open the document's tag picker in portrait and landscape, tap Search tags with the on-screen keyboard up, type a tag name, select it and dismiss the picker. | The search field and matching options remain visible and tappable above the keyboard. Text stays readable without Safari zooming the field, and closing returns focus to the tag trigger. |
| iPad | Long-press prose, adjust the native selection handles, then use the native Copy and Paste menu. | The native selection menu remains usable; selection follows the handles, and pasting inserts the chosen text once without losing the selection or leaving stale editor controls. |
| iPad | Insert Divider from the block menu, tap the line and use the on-screen keyboard's delete key, then undo. Repeat with dividers at either document edge and beside another divider. | A tap selects the divider, the keyboard removes it and undo restores it. The caret can reach a new paragraph on either side without getting stuck. |
| iPad | With Smart Punctuation enabled, type `---` in an empty paragraph, then insert Divider from the block menu. Repeat typing with Smart Punctuation disabled. | Smart Punctuation may turn `--` into a dash and keep the typed text as text. With it disabled, typing `---` inserts a divider and a following empty paragraph. The block menu inserts a divider in either setting. |
| iPad | Enable a Japanese or Chinese keyboard, compose text in prose and a Link or Comment field, choose a candidate, then continue typing. | Candidate selection commits the composed text once; intermediate composition does not prematurely submit a field or choose an editor menu item, and the caret stays at the committed text. |
| iPad | In a Figma caption with bold and italic text and comments on both sides of a line break, add a break with Enter and paste multiple lines. Accept an autocorrection, compose text with a Japanese or Chinese keyboard, choose a candidate and continue typing on each line. | Every stored, typed and pasted line break remains visible and `get_doc` returns it as `\n` with the corrected and composed text. Existing marks and comment excerpts still cover the same words, and composition commits once. |
| MacBook | In Safari, use a Japanese or Chinese input method to compose prose and a Link or Comment field; choose a candidate, continue typing, then undo. | Composition commits once without premature menu activation or field submission; continued typing and undo preserve the text and caret. |
| iPad | Tap a table cell, type with the on-screen keyboard, compose text with a Japanese or Chinese keyboard, and use Enter, Shift+Enter and Paste. | The table remains drawn; text commits once in that cell, each cell remains one paragraph, and no formatting controls show at the caret or during composition. |
| iPad | Long-press text in a header and body cell and adjust the native selection handles within that cell. Tap Bold, Italic, Strikethrough and Inline code; open External link, cancel and then apply a complete URL. Start a Comment. | The popup appears below the range with Comment after formatting. Tapping preserves the selected words, and only those words receive each mark, link or comment highlight. The new thread appears in the rail. The native selection and edit menu remain usable. |
| iPad | Extend a cell selection with native handles into another cell or out of the table, then start a Comment, collapse it or tap elsewhere. | Cross-cell and outside-table ranges offer Comment alone. The composer quotes only the marked text in the first selected cell and says first cell only; collapsing or moving away removes the popup. |
| iPad | With cell text selected, swipe a wide table sideways until the words leave its visible area, then swipe back. | The popup follows the words, hides while they are clipped by the table container and returns with them. The page never scrolls sideways. |
| iPad | Swipe horizontally across a table wider than the document. Tap its last column; with an external keyboard, Tab into an off-screen cell. | The table's own container scrolls, the caret is revealed, and the page and neighboring blocks never widen. |
| iPad | Swipe horizontally across a wide code block, terminal source and drawn terminal screen. In a code block, tap after trailing spaces and type at a long line's end with an external keyboard, then use Copy while scrolled. | Each source panel or screen scrolls internally without widening the page. The code caret stays visible while typing, its caption and copy button stay in place, and Copy includes the whole source and trailing spaces. |
| iPad and MacBook | With a trackpad, scroll a wide table sideways and move between cells with Tab and arrow keys. In the last cell, press Tab. | The table scrolls internally, cell navigation stays usable, and Tab in the last cell adds one body row. |
| iPad and MacBook | With an external keyboard, Tab and Shift+Tab between filled cells, select text using Shift with an arrow, Home or End, press Escape, then select in another cell. Triple-click one cell and extend past its edge using Shift+Arrow. | Navigation, including Tab's whole-cell text selection, shows no popup. A deliberate one-cell text or triple-click selection shows formatting and Comment; Escape closes it without collapsing the range, and a new cell selection can open it. Shift+Arrow into the neighboring cell offers Comment alone, clamped to the first cell. |
| iPad | Tap a table cell, then tap its insertion controls and row menu. Insert a column at either edge, insert a row after the last row, and use Insert row above, Insert row below and Delete row in a body row's menu. | Controls appear without hover, each touch target is at least 44px, each action happens once, every row keeps the same number of cells and the first row remains the only header. Revealing controls does not move cell text or widen the page. |
| iPad | In light and dark appearance, tap a cell in a minimum-width column, then tap the three-dot menu centred on its top border and choose Delete column. Repeat in the first and last columns of a wide table after swiping sideways. Reduce a disposable table to one column and open that menu. | Only the tapped column's menu is revealed without hover; its target is at least 44px and does not overlap the column pluses. Controls follow table scrolling, cell text and the page stay in place, and one deletion removes the header and every body cell in that column. Delete column is unavailable for the last column. |
| iPad | Swipe a wide table sideways and tap insertion controls at its first and last column; open the current row's menu while scrolled. Select cell text and open its formatting popup. | All column and row controls remain reachable within the table's scroll container, and row controls do not collide with the gutter plus or selected-text formatting popup. Native text selection and its callout remain usable. |
| iPad | Tap a body cell, tap its row handle to open the menu, then hold the same handle still and drag the row to another gap. Repeat with a stationary hold, Escape from an external keyboard, and releasing outside the table. Swipe upward immediately from the handle in a tall table; then hold before moving and drag near the pane's top and bottom. | A tap opens the menu. A hold picks up the row without native text selection or the iOS callout, and one gap indicator follows the finger while all rows remain readable. Immediate swipes scroll; after pickup the finger moves the row instead of scrolling the page. Edge scrolling reaches every body gap. A drop moves once; stationary holds and cancellations write nothing. No held gesture also opens the row menu, and the next deliberate tap works. |
| iPad and MacBook | Move a body row one place at a time with Move row up and Move row down in its menu. Reopen from the moved caret using the handle, then undo the move. | The caret follows the row, so repeating the action moves the same row. Up is unavailable for the first body row, Down for the last, and both for the header. The header never moves; undo restores the previous order and each move stays separate from typing. |
| MacBook | In light and dark appearance, hover each column, move the pointer from a cell onto its top-edge three-dot trigger, and open the menu. Close it with Escape, then Tab through its column menus, including columns initially off-screen. Open a menu with Enter and close it with Escape. | Hover reveals only that column's trigger; the caret's column, a focused trigger and an open menu stay revealed. The trigger stays centred on the top border between the pluses without moving cells. Native Tab reveals off-screen triggers, the menu offers only Delete column, and Escape makes no edit and returns usable trigger focus. |
| iPad with an external keyboard | Reach the column menu by tapping a cell and its top-edge three-dot trigger. | Touch reaches the column menu, using normal touch activation without a hold or drag. |
| iPad and MacBook | Archive the disposable document, then tap or right-click table rows. | The table stays drawn and selectable, no structural action is offered and no action changes its cells. |
